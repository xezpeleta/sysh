What it is Usage GitHub

A login shell for unattended AI agents on servers.

Privilege control and accountability — enforced on the server itself.

It exists for sysadmin work you let an agent do alone: sysh bounds what the agent may do, and records what it actually did. It does not promise perfect bounds — an allowed command is still a real command — it promises bounds you set, and a record you can reconstruct the session from.

The problem it solves

When you let an AI agent operate a server, the options are all-or-nothing: give it a root key (it can do anything, silently), or a normal user (it can do little, still silently). Even on a disposable host, the question afterwards is always the same: “it works, but what else did it do? Which files did it change? Which hosts did it touch?”

How it works

sysh makes the agent's SSH login itself the control point. The agent logs in over plain SSH as an unprivileged system user whose login shell does three things, on the server, before any command runs:

Records everything

Every command attempt — allowed or denied — with the full argv, the invoking key, and the outcome, to journald and (opt-in) auditd. The agent cannot forge or erase the record.

Delimits what runs

A root-owned policy of exact commands: literal argv matching, no shell semantics, anchored patterns only, fixed absolute paths, a mandatory linter that rejects escape hatches (shells, find, xargs, git, docker…).

Refuses to elevate

Every process runs under PR_SET_NO_NEW_PRIVS: setuid and sudo are kernel-disabled for the whole agent tree. Root work happens only through operator-written privileged rules — exact-argv sudo grants generated and validated at policy install.

Control lives on the server. Not in the agent's harness, not in prompt instructions, not in a management plane. The agent cannot talk its way past a shell.

Two phases: attended setup, unattended operation

1

Attended preparation

A human with root SSH — often working with a code agent at their side — prepares the host: install the package, write the policy, create the file-access shape the policy assumes (groups, ACLs, ownership), deploy the agent key, run sysh doctor until it is clean. The agent here is an assistant, not autonomous: supervised, interactive, reversible.

2

Unattended operation

The agent connects as sy over plain SSH and works alone inside the bounds the operator set: the exact-argv policy, the OS-level permissions beneath it, no-new-privs, per-exec scopes and resource caps, and full journald/auditd recording.

No human watches each command. The journal is the watch.

What the agent sees, what you see

The agent runs:

ssh -i agent.key sy@server '/usr/bin/uptime'

# a root verb the operator pre-authorized:
ssh -i agent.key sy@server \
  '/usr/bin/systemctl restart wazuh-agent'

# anything else — including sudo itself:
ssh -i agent.key sy@server '/usr/bin/sudo -n id'
→ exit 125, class=denied

You read, on the server:

journalctl -t sysh -n 2 -o verbose
  DECISION=allow
  KEYID=sy/web01.example.net
  ARGV=["/usr/bin/systemctl","restart","wazuh-agent"]
  PRIV=true

# independent second record, from sudo itself:
pam_unix(sudo:session): session opened for user
root(uid=0) by (uid=999)

Honest limits

These bounds are not infallible, and do not need to be. An allowed argv is still a real program with real behavior — tee writes whatever the agent pipes into the file it was granted. What exact-argv matching plus OS permissions buy you is bounded, recorded, root-free-by-default agent access — enough to make unattended AI-agent use on real servers defensible, where the alternatives are “give it a root shell” or “no agent at all”. The threat model, adversary classes and named residuals are written out in PROJECT.md.

It fits your stack

  • One static Go binary, one .deb, no daemon, no management plane, no orchestrator — everything host-local.
  • Any client: scripts, CLI copilots, MCP bridges, humans — if it speaks SSH and passes an argv, it works.
  • Your existing logs: events flow to journald, rsyslog or Wazuh for fleet correlation; your SSH for humans is untouched.
  • Debian/Ubuntu today (deb package; systemd scopes, journald and auditd integration).
