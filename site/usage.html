Usage

The whole lifecycle: the package does the host-local setup, the operator writes the policy and adds the agent key over plain SSH — and from then on anyone the policy allows, human or agent, works inside it.

STEP 1Install

One .deb from the releases page (Debian 12 / Ubuntu 22.04+). The package creates the sy user, installs the sshd drop-in, the tmpfiles.d entries and — if auditd is present — UID-scoped audit rules. No debconf, no daemon.

$ apt install ./sysh_0.4.0_amd64.deb
$ sysh doctor      # 0 failures, 0 warnings before you go further

STEP 2Write the policy

The policy is a root-owned TOML file at /etc/sysh/policy.toml. Rules match the literal argv — fixed absolute paths, anchored patterns, no shell semantics. Install it with the built-in linter:

$ cat > policy.toml <<'EOF'
mode = "enforcing"

[[rule]]
argv = ["/usr/bin/uptime"]

[[rule]]
argv = ["/bin/df", "-h"]

[[rule]]
argv = ["/usr/bin/systemctl", "status", "[a-z0-9@._\\-]+"]

# deny rules have prefix semantics and win over any allow
[[rule]]
argv = ["/usr/bin/"]
action = "deny"
EOF
$ sysh policy install policy.toml

The linter rejects over-broad patterns and known escape-hatch binaries — shells, interpreters, find, xargs, tar, git, ssh, docker… If it complains, the policy does not install: the failure direction is safe.

STEP 3Add the agent key

Generate a dedicated key for the agent and register it by fingerprint. The key's comment becomes its identity in every event:

$ ssh-keygen -t ed25519 -f agent.key -C sy/server.example
$ sysh auth add < agent.key.pub    # forced options: no PTY,
                                   # no forwarding, sysh as the shell

STEP 4Use it

From then on the agent — or you — connects as sy over plain SSH:

$ ssh -i agent.key sy@server '/usr/bin/uptime'
$ ssh -i agent.key sy@server '/bin/df -h'
$ ssh -i agent.key sy@server '/usr/bin/sudo -n id'
{"sysh":1,"class":"denied","detail":"denied by deny rule","exit":125}

Exit codes: 2 lockdown, 3 malformed input, 124 timeout, 125 denied or internal error, 30 approval required, 31 result unavailable. Each exec gets a systemd scope with resource caps; output above the cap trips and is recorded.

STEP 5Root on request: approval rules

Between “never root” and “pre-authorized root” there is a middle: the agent can ask. A rule with approval = true grants nothing standing — each execution waits for a human:

[[rule]]
argv = ["/usr/bin/systemctl", "restart", "[a-z0-9@._\-]+"]
path  = "/usr/bin/systemctl"
privileged = true
approval = true       # root, but only per-exec, human-gated
timeout = 60

At runtime the agent's call exits 30 with a request id and executes nothing. You answer from any root SSH session:

$ ssh -t root@server 'sysh approvals'
req_9b3c1d5e7a42  age=3s  key=sy/server.example
  argv=["/usr/bin/systemctl","restart","mariadb"]
$ ssh -t root@server 'sysh approve req_9b3c1d5e7a42'
  execute as root? [yes/no] type argument 2 exactly as shown (mariadb):
executed: exit=0 in 213ms

The approver re-reads the argv on screen and types any pattern-chosen argument by hand; a mismatch aborts and the request stays pending. The agent then fetches the outcome read-only — sysh-result req_…, exit 31 while pending, expired, or never approved. The journal holds both halves: request events from the agent's side, approve events from root's (_UID=0). Requests expire after 10 minutes, results after an hour; there is nothing to revoke because nothing was ever granted.

Signed approvals bind approval power to registered approver keys — for headless or remote operation, and for FIDO2-grade assurance. Register your key once (an sk-* hardware key means no signature can exist without your physical touch):

root@server# sysh approver add ops-yubi
paste one public key line, then Ctrl-D
registered approver ops-yubi (sk-ssh-ed25519@openssh.com)

Then approve from anywhere, signing the exact request bytes with stock tooling:

$ ssh root@server 'sysh approve req_9b3c1d5e7a42 --show' > req.body
$ ssh-keygen -Y sign -f ~/.ssh/id_ed25519_sk -n sysh-approve req.body
$ cat req.body.sig | ssh root@server 'sysh approve req_9b3c1d5e7a42 --sig'
approved by ops-yubi (SHA256:…); executed: exit=0 in 198ms

The signature is verified in-process on the server, bound to the request’s exact bytes and the sysh-approve namespace; an unregistered key, a wrong file, a replayed signature — all refused, request stays pending. The typed-argument challenge of interactive approve still applies to pattern rules.

One command wraps the whole ceremony — sy approve, run by you in your terminal (never a tool the agent can call): it fetches the request bytes from the server over your root SSH channel, shows the server-recorded argv, and runs the sign+submit with your approver key (YubiKey PIN and touch happen inside):

op@laptop$ sy approve req_9b3c1d5e7a42
┌─ sysh approval request req_9b3c1d5e7a42 ──────────────
│  key: sy/server.example (claimed)  age: 8s
│  argv: /usr/sbin/reboot
└─ sign with your approver key to authorize exactly this ──
authorize exactly this? type yes to sign: yes
insert your YubiKey… (waiting up to 30s)
authenticator detected
signature ok: approver ops-yubi (…); executed: exit=0 in 30ms

The display comes from the server through your own channel — the agent cannot fake that screen, which is exactly why the approval gesture lives here and not in agent tool space.

STEP 6Root verbs: privileged rules

For work that needs root, the operator pre-authorizes exact argvs. Install generates a root-owned sudoers fragment limited to those argvs — nothing else:

[[rule]]
argv = ["/usr/bin/systemctl", "reload", "apache2"]
path  = "/usr/bin/systemctl"
privileged = true
ack  = true          # required: you said so, out loud
timeout = 60

At runtime the gateway wraps the exec in sudo -n --; events carry PRIV=true with the agent's argv, and sudo writes its own independent PAM journal line. The trade-off — no-new-privs must be dropped for the tree while such rules exist, and sudo's TIMEOUT= enforces the deadline — is documented in PROJECT.md §6.8.

Profiles: composing with OS permissions

Fine-grained shapes come from composing the argv policy with ordinary OS permissions, prepared in the attended phase. The worked example — an agent-maintained web server: read the Apache config tree and logs, write the enumerated config files, validate, reload — lives in examples/webserver/:

# OS side (operator, once): ACLs carry the log reads — no groups needed
setfacl -m u:sy:rX /var/log/apache2
setfacl -d -m u:sy:r /var/log/apache2      # survive logrotate

# policy side: the verbs (privileged rules are exact argv)
[[rule]]  argv = ["/usr/bin/tail", "-n", "[0-9]+", "/var/log/apache2/error.log"]
[[rule]]  argv = ["/usr/sbin/apache2ctl", "configtest"]   # privileged
[[rule]]  argv = ["/usr/bin/tee", "/etc/apache2/ports.conf"]  # privileged
[[rule]]  argv = ["/usr/bin/systemctl", "reload", "apache2"]  # privileged
[[rule]]  argv = ["/usr/bin/systemctl", "restart", "[a-z0-9@._\-]+"]  # approval-gated

The agent then maintains that server — config content on stdin through tee, validate, reload — and nothing else. A full restart drops live connections, so it goes through the approval channel: the agent can only request it, a human answers.

STEP 7Agent harnesses: sy mcp

The same package ships sy, the agent-side client. Point your MCP-capable harness (Pi, Claude Desktop, anything that speaks stdio MCP) at sy mcp and it gets three tools: sy_exec, sy_docs, sy_policy — nothing more. Hosts live in an operator-edited registry (~/.config/sy/hosts.toml), connections are plain SSH as the unprivileged sy user with strict known_hosts; the server-side policy is the only authority. When an exec needs root approval, the tool result carries the request id and tells the agent to stop — approval power never appears in tool space.

$ cat ~/.config/sy/hosts.toml
default = "web01"
[hosts.web01]
address = "web01.example.net"     # your host
key     = "~/.config/sy/keys/web01.ed25519"
$ ssh-keyscan web01.example.net >> ~/.config/sy/known_hosts  # all key types: servers may present ecdsa first
$ echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | sy mcp

Reading the record

$ journalctl -t sysh --since today    # every exec attempt, both phases
$ ausearch -k sysh_exec               # kernel-side: files touched, network
$ sysh doctor                         # drift and tripwire check
$ sysh lockdown                       # panic button: drop the key, exit 2
