Usage

The whole lifecycle: the package does the host-local setup, the operator writes the policy and adds the agent key over plain SSH, and from then on anyone the policy allows — human or agent — works inside it.

1 · Install

One .deb from the releases page (Debian 12 / Ubuntu 22.04+). The package creates the sy user, installs the sshd drop-in, the tmpfiles.d entries and (if auditd is present) UID-scoped audit rules. No debconf, no daemon.

apt install ./sysh_0.1.0_amd64.deb
sysh doctor   # 0 failures, 0 warnings before you go further

2 · Write the policy

The policy is a root-owned TOML file at /etc/sysh/policy.toml. Rules match the literal argv — fixed absolute paths, anchored patterns, no shell semantics. Install it with the built-in linter:

cat > /etc/sysh/policy.toml <<'EOF'
mode = "enforcing"

[[rule]]
argv = ["/usr/bin/uptime"]

[[rule]]
argv = ["/bin/df", "-h"]

[[rule]]
argv = ["/usr/bin/systemctl", "status", "[a-z0-9@._\\-]+"]

# deny rules have prefix semantics and win over any allow
[[rule]]
argv = ["/usr/bin/"]
action = "deny"
EOF
sysh policy install /etc/sysh/policy.toml

The linter rejects over-broad patterns and known escape-hatch binaries (shells, interpreters, find, xargs, tar, git, ssh, docker…). If it complains, the policy does not install — the failure direction is safe.

3 · Add the agent key

Generate a dedicated key for the agent and register it by fingerprint: the key's comment becomes its identity in every event.

ssh-keygen -t ed25519 -f agent.key -C sy/server.example
sysh auth add < agent.key.pub     # authorized_keys, options forced
                                    # (no PTY, no forwarding, forced sysh)

4 · Use it

From then on the agent — or you — connects as sy over plain SSH:

ssh -i agent.key sy@server '/usr/bin/uptime'
ssh -i agent.key sy@server '/bin/df -h'
ssh -i agent.key sy@server '/usr/bin/sudo -n id'
→ {"class":"denied","detail":"denied by deny rule",...}  exit 125

Exit codes: 2 lockdown, 3 malformed input, 124 timeout, 125 denied or internal error. Each exec gets a systemd scope with resource caps; output above the cap trips and is recorded.

5 · Root verbs: privileged rules

For work that needs root, the operator pre-authorizes exact argvs. Install generates a root-owned sudoers fragment limited to those argvs — nothing else:

[[rule]]
argv = ["/usr/bin/systemctl", "restart", "wazuh-agent"]
path  = "/usr/bin/systemctl"
privileged = true
ack  = true          # required: you said so, out loud
timeout = 60

At runtime the gateway wraps the exec in sudo -n --; the events carry PRIV=true with the agent's argv, and sudo writes its own independent PAM journal line. The trade-off — no-new-privs must be dropped for the tree while such rules exist, and sudo's TIMEOUT= enforces the deadline — is documented in PROJECT.md §6.8.

Profiles: composing with OS permissions

Fine-grained shapes come from composing the argv policy with ordinary OS permissions, prepared in the attended phase. The worked example — “read and modify the Wazuh agent config as an unprivileged user, restart as the single root verb” — lives in deployments/unifi/README.md:

# OS side (operator, once): a file-access group is sy's ceiling
groupadd sysh-wazuh-cfg && usermod -aG sysh-wazuh-cfg sy
chgrp sysh-wazuh-cfg /var/ossec/etc/ossec.conf   # 0664

# policy side: the verbs
[[rule]]  argv = ["/usr/bin/cat", "/var/ossec/etc/ossec.conf"]
[[rule]]  argv = ["/usr/bin/tee", "/var/ossec/etc/ossec.conf"]
[[rule]]  argv = ["/usr/bin/systemctl", "restart", "wazuh-agent"]
          privileged = true, ack = true, timeout = 60

The agent then manages that config file — content on stdin through tee — and can restart the service, and nothing else.

6 · Read the record

journalctl -t sysh --since today     # every exec attempt, both phases
ausearch -k sysh_exec                # kernel-side: files touched, network
sysh doctor                          # drift and tripwire check
sysh lockdown                        # panic button: drop the key, exit 2
